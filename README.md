# Larkzee Chat

Larkzee Chat 是一个面向 Windows 局域网的轻量点对点聊天工具，支持文字、表情、图片和文件。两台电脑运行相同版本的程序，其中任意一台开启连接服务并分享 8 位连接码，另一台输入连接码即可自动取得局域网 IPv4 地址和认证凭据。程序不需要中央服务器、账号或数据库，也不保存聊天记录；旧式手工 IP + 密码连接仍然保留。

聊天消息只存在于当前进程内存和聊天窗口中，关闭程序后立即清空，不会写入配置文件或日志。普通文件接收时，接收方必须先选择最终保存位置，程序才开始传输；传输内容直接写入该目录中的 `.larkzee-<传输ID>.part` 临时文件，不使用应用缓存目录。只有大小和 SHA-256 都校验通过后才原子改名为最终文件；拒收、取消、失败或断线都会删除未完成的 `.part`。聊天图片和自定义表情会自动接收并直接显示在聊天框中，只在当前进程内存中保留，不写入接收文件或应用缓存；在图片或表情上右键选择“另存为…”时才打开保存对话框。自定义表情包属于用户主动导入的本地素材，持久保存在 `%LocalAppData%\LarkzeeChat\EmojiPacks`，不上传到网络。为避免长时间连续运行导致界面控件无限增长，当前窗口最多保留最近 24 小时、500 条且累计 100,000 个字符以内的消息；任一上限触发后会从最旧消息开始清理。

当聊天窗口不在前台时，新收到的消息会让 Windows 任务栏按钮持续闪动；切回聊天窗口后自动停止，不会弹出打断操作的提示框。

## 首次使用

1. 两台电脑分别运行 `LarkzeeChat.exe`。
2. 接收连接的一方打开“⚙ 配置”，确认程序显示的“本机 IP”；电脑有多个网卡时选择双方实际互通的那个地址，然后开启“允许其他电脑连接”。
3. Windows 首次询问防火墙权限时，仅允许“专用网络”。程序不会自动修改防火墙，也不需要管理员权限。
4. 将界面生成的 8 位“我的连接码”告诉另一方。连接码只使用小写字母和数字，并排除容易混淆的 `0`、`1`、`i`、`o`。
5. 另一方在“⚙ 配置”中填写“对方连接码”，保存后回到主窗口点击“连接”。程序会先检查连接码，再自动填写对方 IP 和认证密码。
6. 任意一方可点击“断开”。若网络中断或程序关闭，另一方会静默回到未连接状态，不弹出断线提示框，也不会清掉尚未发送的输入内容。

## 表情、图片和文件

- “表情”按钮提供 40 个常用 Unicode 表情；也可以直接粘贴或使用系统输入法输入其他 Unicode 表情。选择“我的表情”后，可导入多个 PNG/GIF 文件到“自定义”，或导入一个文件夹作为独立表情包。
- 自定义表情包可以在表情选择窗口中刷新、删除、打开存储目录；导入完成后会复制到 `%LocalAppData%\LarkzeeChat\EmojiPacks`，删除原始文件不会影响已导入的副本。
- 自定义表情只支持 PNG 和 GIF，单个文件必须大于 0 且不超过 1 MiB。发送前必须已连接对方；发送后以紧凑图片气泡显示。图片或表情传输成功后隐藏进度与校验提示，只保留图片和时间；右键气泡中的图片可以“另存为…”。GIF 是否动画取决于 Windows 版本和 WinForms `PictureBox` 的系统支持。
- “图片”支持 PNG、JPEG、GIF、BMP 和 WebP，单个图片以内存方式接收，最大 25 MiB；聊天框直接显示预览，右键“另存为…”才写入用户选择的位置。无法解码预览时仍保留原始字节并允许另存为。
- “文件”可发送任意文件，单个附件上限为 256 MB；同一方向一次只发送一个附件。
- 接收方只会为普通文件看到保存对话框，可以修改文件名和保存目录，也可以取消接收；确认保存位置之前不会传输文件内容。图片和表情自动接收并显示在聊天框中。
- 普通文件传输气泡显示准备、等待保存位置、传输进度、校验和最终结果。成功后可点击“打开文件夹”定位文件；程序不会自动打开收到的文件。图片和表情不显示“对方校验通过”等技术状态。
- 图片和文件使用 24 KiB 分块，通过现有 AES-256-GCM 会话加密发送。最终完成状态以接收方 SHA-256 校验结果为准。

连接服务固定监听 IPv4 `0.0.0.0:45678`。本机 IP 和连接码仅显示在配置窗口；主聊天窗口不会显示任何网络或身份技术信息。连接码支持 RFC1918 私网地址：`10.x.x.x`、`172.16.x.x`–`172.31.x.x` 和 `192.168.x.x`。

对方连接码、IP、本机认证密码和对方认证密码保存在 `%USERPROFILE%\.larkzeeChat\settings.json`。连接码和密码使用 Windows DPAPI 的 `CurrentUser` 范围保护，配置文件中不写入这些值的明文；同一 Windows 用户再次启动程序时会自动读取。更换 Windows 用户或无法解密配置时，需要重新设置。每次重新开启本机连接服务都会生成新的连接码，旧码不应继续分享；修改凭据只影响之后建立的新连接，不会中断当前已经加密的聊天会话。

## 连接码校验与安全边界

8 位连接码由 7 位数据和 1 位 GF(32) 校验字符组成。它保证任意一个字符被替换时都能检测出来，也能检测绝大多数两个字符同时输错的情况，但不能保证所有双字符错误都被发现，更不会自动猜回正确字符。若需要“所有双错必检、一个字符输错可自动纠正”，格式至少需要扩展为 9 位并使用两个校验字符。

连接码是一种紧凑编码，不是加密文本：任何拿到连接码的人都能解析 IP 并派生认证凭据。三位临时口令只提供很低的配对强度，因此本功能只适合可信局域网和低安全场景；不要在公网或不可信网络中使用，也不要把连接码当作长期密码。

## 构建与发布

需要 .NET 8 SDK：

```powershell
dotnet restore
dotnet build -c Release
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

默认发布文件位于：

```text
bin\Release\net8.0-windows\win-x64\publish\LarkzeeChat.exe
```

发布结果是 Windows x64、自包含、单文件应用，目标电脑不需要单独安装 .NET Runtime。

仓库中的可分发文件有两种，请不要混用：

- `dist\LarkzeeChat-v1.3.0-win-x64\LarkzeeChat.exe`：推荐拷贝到其他电脑使用；已经包含 .NET 8 Desktop Runtime，目标电脑无需另行安装运行环境。
- `dist\LarkzeeChat-v1.3.0-win-x64-lite\LarkzeeChat.exe`：小体积版本，只适合已经安装 .NET 8 Desktop Runtime x64 的电脑；裸机双击可能无法启动。
- 两个目录中的 `LarkzeeChat.exe.md5` 分别记录对应 EXE 的 MD5，复制后可用于完整性核对。

`dist/` 是本地发布输出目录，已从 Git 跟踪中排除。

## v2 安全边界

连接认证使用连接码派生凭据（或兼容模式下的手动密码）、随机 Challenge、每次连接新生成的 NIST P-256 ECDH 密钥对和 HMAC-SHA256 双向证明；凭据本身不会作为认证报文发送。认证失败会按来源 IP 限流。协议 v2 不兼容旧的明文版本，两台电脑必须同时更新。

认证成功后，聊天、心跳和断开报文都使用每个连接独立派生的 AES-256-GCM 会话密钥加密，并带有严格递增的方向序号，可检测篡改、重放和乱序。会话密钥只存在于当前连接内，断开或重连后不会复用。

v1.1.0 在加密会话中增加附件协商、分块、完成和校验回执。v1.2.0 在此基础上增加 PNG/GIF 自定义表情包和内存接收。v1.3.0 增加聊天图片内存接收、气泡内预览、右键另存为，以及长文本气泡的准确换行高度。旧版本不认识这些消息类型，因此发送图片、文件或自定义表情时两端必须同时使用 v1.3.0；文字聊天仍要求两端使用兼容的 v2 加密协议版本。v1.3.0 的本地表情包目录和元数据为应用内部格式，不能直接作为 v1.1.0 或更早版本的表情包使用。

安全边界：短连接码可被抓包者离线枚举，手动模式下的弱密码也可能被离线猜测；DPAPI 主要防止配置文件被直接复制后读取，已在同一 Windows 用户身份下运行的恶意程序仍可能访问凭据。网络上的地址、报文长度和时间等元数据也不会被隐藏。请仅在可信的本地局域网使用。
